Three groups, seven views: the Project Intake Process, a standalone Portfolio Review, and Project Status governance tools. Pick a page below to begin.

Project Intake Process

2 linked steps
1. Intake Form

Project Intake Form

Always live. Auto-generates the Request ID and system date, enforces required (*) fields, and unlocks the review section only after the request is submitted.
2. Intake Report

Project Intake Report

A locked, display-only register of every intake submission, each shown with its current status colour. Reads directly from the form.

Portfolio Review

standalone
1. Portfolio Review

Weekly Portfolio Review

The current reporting cycle's project data set, and nothing else. This is the master source that drives the scorecard.

Project Status

4 governance views
1. Project Scorecard

Weekly Scorecard

Pick any project from the portfolio; its manager, dates, phase, % complete and schedule status populate automatically from the portfolio review.
2. Risk & Decision

Risk & Decision Log

Two tabs, one page: the open/closed Risk & Issue register and the Decision Log, in the same format used to run weekly governance reviews.
3. Repository

Project Repository

The OPA folder structure for a project — Requirement Initiation through Project Closure — browsable as a live document tree with sample files.
4. Change Request

Change Implementation Form

A CIF-style deployment change form: requestor details, change & rollback plan, IT systems and networks sign-off, and implementation status — all logged locally.
How the groups are linked
Intake Form → Intake Report   (submissions populate the read-only register)
Portfolio Review → Project Scorecard   (portfolio data drives every derived scorecard value)
Risk & Decision, Repository, and Change Request are standalone governance and document-control tools on the same shared data layer.
Demo data is seeded on first load. Your intake submissions are added on top of it.
